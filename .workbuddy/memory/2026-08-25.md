## 后台原型修复：留言"待处理"子菜单无响应（2026-08-26 续）

- **问题**：admin.html 侧栏"留言管理"下的"待处理"子菜单点击后无内容显示
- **根因**：子菜单 `data-page="messages-pending"`，但没有 `view-messages-pending` 视图，`go()` 找不到目标视图 → 页面无任何变化
- **修复**：
  1. 子菜单改为复用 `view-messages` 视图，`data-page="messages"` + `data-filter="待处理"`（"全部留言" `data-filter=""`）
  2. 点击子菜单时：正确高亮当前项（不依赖 querySelector 首个匹配）+ `go('messages')` + 设置状态筛选下拉值 + 调用 `applyMsgFilter()`
  3. 新增 `applyMsgFilter()`：给留言表格每行加 `data-status`（待处理/处理中/已回复），根据下拉值显示/隐藏行，并更新计数文案
  4. 筛选下拉绑定 `change` 事件联动过滤
- **实测**：点击"待处理" → 视图正常、下拉=待处理、可见行=待处理×2、计数="共 2 条（筛选：待处理）"；JS 语法通过
- **经验**：
  - 侧栏子菜单与页面视图必须一一对应；没有独立视图时复用父视图 + 筛选参数联动是最简方案
  - "没有出现信息"类问题优先检查 `data-page` 是否有对应 `view-*` 容器

## 后台原型修复二：留言筛选失效根因（嵌套 tr）+ 移除待处理子菜单（2026-08-26 续）

- **用户反馈**：1) 去掉侧栏留言管理"待处理"子菜单；2) 留言筛选仍无效
- **筛选失效根因（重要）**：为表格行加 `data-status` 时用了错误替换：
  `new = '<tr data-status="X">' + old.split('>')[0] + '>'` → 产生 `<tr data-status="X"><tr>` **嵌套 tr**（5 行变 10 行），且 `old.split('>')[0]` 只保留了 `<tr`，**丢弃了姓名单元格** `<td><div class="cell-name">…</div></td>`，导致每行姓名丢失、DOM 结构错乱
- **修复**：整体重写 view-messages 的 tbody（5 行，含 cell-name + data-status + 操作列 openMessage(n)），用 `re.sub` 清理嵌套 tr 后以正确定位（view-messages section 内第一个 tbody）替换
- **筛选实现**：`applyMsgFilter()` 根据筛选下拉值显示/隐藏行并更新计数；select 绑 change；侧栏"留言管理"恢复单级菜单（移除 sb-sub + arrow）
- **实测**：表格 5 行（张先生/李女士/王经理/赵小姐/陈先生）；筛选 待处理→2 条、已回复→2 条、全部→5 条，计数联动；侧栏无子菜单，点击直接进留言视图
- **经验**：
  - Python 字符串替换构造 HTML 时，`split('>')[0]` 截断会丢弃标签后的内容 → 应直接拼接完整新标签，或整体重写块
  - 表格行加属性要保证 `<tr>` 开标签唯一且后续内容完整；修复后必须浏览器实测行数、姓名、状态三项
  - 后台筛选最稳的实现：行级 `data-status` + 容器级事件监听 + 统一过滤函数
